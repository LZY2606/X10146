# WAL 恢复沙盒（WAL Recovery Sandbox）

一个**纯 Java、无现成数据库依赖**的本地教学沙盒，用于直观演示 write-ahead log
（预写日志）的崩溃/重启语义。使用者在网页上编辑键值事务、逐条把 begin/put/delete/
commit/checkpoint 记录追加到日志，查看每条帧的十六进制字节，然后在指定字节、指定
完整记录之后或某个 checkpoint 阶段模拟掉电。重启时程序只扫描**实际落盘的前缀**，
判断哪些事务可以重做、哪些必须丢弃，并把恢复后的键值状态与每一步判定依据展示出来。

## 运行

需要 JDK 17。已提交 Gradle Wrapper（Gradle 8.10.2）。

```bash
./gradlew classes                 # 必须成功
./gradlew test                    # 18 个测试
./gradlew run --args='--host 127.0.0.1 --port 5226'
```

浏览器打开 <http://127.0.0.1:5226>，页面标题为 **“WAL 恢复沙盒”**。

运行时数据写在 `./sandbox-data/`（已 gitignore）：`experiments/*.json` 保存实验
脚本与故障配置，`media/<exp-id>/` 保存物化后的**原始字节**（日志段与快照）。

## 帧格式

每条日志帧为：`int payloadLength | byte type | long txnId | int seqNo | int crc32 | payload`
（整数均为大端；CRC 覆盖 crc 之前的 17 字节头部与载荷）。类型：`BEGIN=1、PUT=2、
DELETE=3、COMMIT=4、CHECKPOINT=5`。扫描器严格区分四种扫描结尾：

- 干净 EOF：最后一条帧恰好结束；
- 截断帧头：不足 21 字节；
- 截断载荷：头部完整但声明的载荷没完全落盘；
- 长度荒谬（尾部垃圾/长度位被破坏）；
- 校验失败：帧完整但 CRC 不符；
- 未知类型：帧完整、CRC 正确，但类型字节无法识别。

**只有“完整且校验通过”的 COMMIT 链才生效。** 同一事务的记录必须具备从 1 开始、
逐条连续的序号；缺号、重复 BEGIN、没有 BEGIN 的 PUT/COMMIT 等都会使整个事务被丢弃。

## 事务与 checkpoint

- put/delete 在 COMMIT 之前只是“待提交”效果；commit 帧未完整落盘则整个事务丢弃。
- checkpoint 采用**写临时文件 → fsync 临时文件 → 原子替换 → fsync 目录 → 写日志
  checkpoint 标记帧 → 轮转新段**的阶段模型。快照带魔数、代次、尾部校验，只有完整
  且校验通过的快照才会被选中，因此任何阶段崩溃后，恢复只能看到**完整旧快照**或
  **完整新快照**之一（残留 `.tmp`/被撕裂的最终文件一律忽略）。
- 日志轮转后，每个段文件头部内嵌“代次（segment index）”。恢复先认快照代次，再从
  快照要求的段开始按**头部代次**选择连续段；缺代次却存在更晚段时判定为“日志段
  缺口”并停止，**绝不按文件名字符串猜测**（重命名的段仍能被正确识别）。
- 恢复是只读的：重复恢复得到相同状态，且已 checkpoint 的操作物理上不会被重读，
  因此不会被重复施加。

## 故障开关（只影响被选中的那一次写入）

短写、尾部垃圾、位翻转、未知类型、checkpoint 中断。每个实验都物化为独立目录，
因此故障不会污染后续实验。崩溃点可选：某事件之后、N 条完整记录之后、B 字节之后、
checkpoint 某阶段。

## 持久化与导出

所有实验脚本、故障配置和**原始字节**都持久化。点击“导出 zip”可下载
`experiment.json` + `media/`；在一个全新的空实例上“导入 zip”会还原出完全相同的
原始字节与恢复轨迹（有测试保证）。

## 测试覆盖

`src/test/java/wal/`：空日志、截断头/截断载荷、坏校验、未知类型、未提交事务、
短写、尾部垃圾、checkpoint 各崩溃阶段、重复恢复幂等、日志段缺口、按段头识别重命名
段、事务序号不连续、以及导出/导入恢复轨迹一致性。
